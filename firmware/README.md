# Прошивка сканера HARIZMA (ESP32-S3)

**`scanner_firmware.cpp` — актуальная рабочая прошивка** системы учёта посещаемости
UCHETZP. Это эталон-источник: при заливке всегда брать его. Предыдущие рабочие версии
заморожены в [`archive/`](archive/) — оттуда откатываются, если новая окажется хуже.

> ⚠️ **Устройство ещё не перепрошито версией 2.0.0.** Пока не зальёте — в сканере живёт
> старая прошивка, которая шлёт отметки на мёртвый Vercel-адрес и ничего не знает про
> мониторинг. Первую заливку придётся сделать руками (OTA из локальной сети или USB) —
> дальше всё обновляется из админки.

## Ключевые параметры

| Параметр         | Значение                                                  |
|------------------|-----------------------------------------------------------|
| Версия           | `FW_VERSION` = **2.6.0**                                  |
| Платформа        | ESP32-S3 (Arduino framework)                              |
| Сервер (API)     | `https://zp.haskyhub.com`                                 |
| Отметки          | `POST /api/attendance/bulk-scan`, `{"scans":[{"card_id":"...","timestamp":"..."}]}` |
| Состояние        | `POST /api/scanner/heartbeat` раз в 30 с (настраивается)   |
| RFID-ридер       | UART (Serial2), пин RX = 16, 9600 8N1, кадр `STX … ETX`   |
| Экран            | ST7735 1.44" (SPI)                                        |
| Подсветка        | WS2812B, 12 диодов, пин 15                                |
| Звук             | I2S (BCLK 5 / LRC 6 / DOUT 7); канал поднимается только на время звука |
| Кнопки           | UP = 1, DOWN = 2, OK = 46 (долгое нажатие — меню)         |
| Батарея          | ADC пин 4, делитель ×2                                    |
| Wi-Fi            | WiFiManager (портал настройки `HARIZMA_SETUP`)            |
| Время            | синхронизация по NTP, пояс `EET-2EEST`                    |
| Обновление       | **из админки по воздуху** + ArduinoOTA по локалке (`HARIZMA-SCANNER`) |
| Офлайн-режим     | очередь сканов в LittleFS (`/offline.jsonl`), досыл пачкой |
| Энергосбережение | deep sleep вне рабочих часов, с короткими выходами на связь |

## Что делает устройство

- Читает RFID-карты и регистрирует отметки прихода/ухода.
- Дисплей с UI: главный экран с часами, меню, громкость, настройка Wi-Fi.
- При отсутствии интернета отметки копятся в `offline.jsonl` и досылаются при появлении связи.
- Раз в 30 секунд отчитывается серверу о своём состоянии и забирает команды.
- Ночью и в выходные спит, но раз в 30 минут просыпается на несколько секунд — отметиться
  и проверить, нет ли команд.

## Настройка перед первой заливкой

1. Придумайте общий секрет и задайте его на сервере в переменной окружения
   **`SCANNER_DEVICE_KEY`**. Без неё эндпоинты сканера отключены — сервер отвечает 503.
2. Впишите тот же секрет в `scanner_firmware.cpp`:
   ```cpp
   const char* DEVICE_KEY = "CHANGE-ME";   // ← сюда
   ```
3. Соберите и залейте.

Ключ — единственное, что защищает эндпоинты: через них можно перезагрузить железо и
стереть неотправленные отметки. В репозиторий его класть не стоит.

## Связь с сервером: почему именно так

Сканер стоит за NAT — у него нет внешнего адреса, и сервер к нему подключиться **не может**.
Поэтому связь односторонняя: устройство само стучится наружу, а сервер отвечает тем, что
успело накопиться.

```
Сканер ──POST /api/scanner/heartbeat──▶ Сервер
   {я жив, RSSI -54, батарея 87%, очередь 3, аптайм 4 ч}
        ◀──────────── ответ ────────────
   {"commands":[{"id":17,"command":"reboot"}], "config": {...}, "ota": {...}}
```

Отсюда два следствия, которые важно помнить:

- **Команда выполняется не мгновенно**, а в пределах одного интервала heartbeat.
- **Спящий сканер команд не получает** — они дождутся ближайшего ночного выхода на связь.

### Что уходит в heartbeat

`fw_version`, режим (`active` / `night` / `presleep`), версия конфига, IP, SSID, RSSI,
заряд и напряжение батареи, длина очереди, свободная память, аптайм, причина последней
перезагрузки (`esp_reset_reason` — сразу видно, был ли сбой), синхронизировано ли время,
текст последней неудачи обновления.

### Команды из админки

| Команда         | Что делает |
|-----------------|------------|
| `reboot`        | `ESP.restart()`. Отчитывается серверу **до** перезагрузки, иначе команда навсегда зависла бы в статусе «отправлена» |
| `clear_queue`   | Удаляет `/offline.jsonl`. **Неотправленные отметки теряются безвозвратно** |
| `flush_queue`   | Досылает очередь немедленно, не дожидаясь 10-секундного цикла |
| `identify`      | Бип + радуга на подсветке — найти устройство, проверить звук и ленту |
| `reload_config` | Сбрасывает версию конфига, чтобы сервер прислал настройки заново |

### Настройки, управляемые с сервера

Лежат в `/config.json` на LittleFS — переживают перезагрузку и сон. Сервер присылает их
только когда `config_version` выросла, а не в каждом ответе.

| Ключ | Смысл |
|---|---|
| `heartbeat_sec` | интервал выхода на связь (10–3600) |
| `sleep_enabled` | засыпать ли вне рабочих часов |
| `work_start` / `work_end` | «ЧЧ:ММ» — когда просыпаться и засыпать |
| `work_days` | список 1 (Пн) … 7 (Вс); в остальные дни спит целиком |
| `night_checkin_min` | во сне выходить на связь раз в N минут; `0` — не просыпаться до утра |
| `volume_percent`, `led_brightness` | громкость 0–100, яркость 0–255 |
| `debounce_sec` | окно игнорирования повторного скана той же карты |
| `no_sleep_until` | режим обслуживания: до этого времени не спать |

Пустой `work_days` сервер и прошивка отвергают: иначе сканер уснёт навсегда, и разбудить
его можно будет только кнопкой питания.

### Ночные выходы на связь

Вместо одного долгого сна до утра устройство спит кусками по `night_checkin_min` минут.
Проснувшись, оно **не поднимает** экран, подсветку, звук и ридер — только Wi-Fi: отчитаться,
досыпать накопившиеся отметки, забрать команды и заснуть обратно. Один такой выход стоит
примерно 0,25 мА·ч, то есть за ночь набегает около 5 мА·ч.

Признак «мы внутри ночного цикла» хранится в RTC-памяти (`rtcNightMode`) — обычные
глобальные переменные deep sleep не переживают.

### Обновление по воздуху из админки

Админ загружает `.bin` на странице «Сканер», сервер отдаёт его устройству, устройство
скачивает и ставит само. Работает из любой сети, в отличие от ArduinoOTA.

- Авторизация — Basic (`HTTPUpdate` другого не умеет), пароль = тот же `DEVICE_KEY`.
- Контрольную сумму `HTTPUpdate` берёт из заголовка `x-MD5` и сверяет до записи.
- **Версия при загрузке должна совпадать с `FW_VERSION` внутри прошивки** — сервер по ней
  понимает, что обновление доехало. Не совпадёт — устройство будет обновляться по кругу.
- Одна и та же сборка не ставится больше трёх раз подряд: битый `.bin` иначе загонит
  сканер в вечный цикл скачивания. Счётчик в RTC-памяти, сбрасывается перезагрузкой.

## Сборка

Открыть `scanner_firmware.cpp` в Arduino IDE / PlatformIO.

Библиотеки: `WiFi`, `WiFiClientSecure`, `HTTPClient`, **`HTTPUpdate`**, `LittleFS`,
`FastLED`, `Adafruit_GFX`, `Adafruit_ST7735`, `U8g2_for_Adafruit_GFX`, `WiFiManager`,
`ArduinoOTA`, **`ArduinoJson` (7.x)**, `esp_task_wdt`, драйвер `driver/i2s_std.h`.

Жирным — то, что добавилось в версии 2.0.0. `ArduinoJson` обязательно **седьмой** версии:
код использует `JsonDocument` без указания размера, в 6.x такого API нет.

Разметка флеша должна быть с двумя слотами приложения (любая схема с `ota_0`/`ota_1`) —
без этого не работает ни ArduinoOTA, ни обновление из админки.

## Важно

Прошивка обновляется по воздуху, поэтому версия, физически залитая в сканер, может
отличаться от этого файла. Этот файл — эталон-источник; что стоит на устройстве сейчас,
видно в админке на странице «Сканер».
